# Demo BTC liquidity probe

`btc-liquidity-probe-v1` is a one-time test of the provider-backed decision and order trail. It makes no claim that buying BTC has positive expected return. The fixed small notional tests eToro Demo execution while bounding the capital at risk to $100 of virtual funds. It is separate from the simulated AAPL/MSFT research scenarios.

The system records a **HOLD** unless all of these official eToro observations pass:

1. A schema-valid Demo account read is at most two minutes old, has a provider account ID, uses USD, has at least $500 available cash, and values the $100 plan at no more than 1% of the account. Aggregate holdings and copies are empty; the separate Demo P&L read has no positions or pending orders. The account ID is held as an HMAC fingerprint and must match again at execution.
2. Exact `BTC` instrument search says the instrument is tradable and buyable. A realtime bid/ask quote is at most 30 seconds old, not crossed, and has spread at most 50 basis points.
3. Account-specific eligibility permits a $100 unlevered long in the **real** BTC instrument, with minimum position size no greater than $100. The current what-if estimate is at most two minutes old, has only recognized USD cost types, no nonzero ongoing fees, and upfront costs at most $2.

Passing preview creates a durable plan valid for 60 seconds. It shows the quote, source digests, checks, estimated upfront costs and a buy limit rounded up to cents at 0.2% above the observed ask. An explicit execute action repeats the provider checks and rejects a moved quote above that reviewed limit. It persists the intent and broker request ID before a single `limitIOC` submission to the **Demo** v2 order endpoint. That order can fill immediately, partially fill, be cancelled/rejected, or remain uncertain. A successful submission response is only `accepted`; the official lookup by original request ID supplies the broker state and position IDs. Ambiguous submissions are never resubmitted. Every successful raw provider response is encrypted in PostgreSQL.

If filled, the BTC position remains in the Demo account for observation in the scheduled portfolio snapshots. There is **no automatic exit, stop loss, fill accounting ledger, virtual sleeve allocation or claim of strategy performance** in this version. Review the broker position and account snapshots after the test; a later exit requires a separately designed and authorized close workflow. The shared operator token authenticates both human and agent calls to the same API, but it does not identify an individual person.

Official API references: [Demo order creation](https://api-portal.etoro.com/api-reference/trading--demo/create-an-order), [order lookup](https://api-portal.etoro.com/api-reference/trading--demo/get-order-information-and-position-details), [Demo eligibility](https://api-portal.etoro.com/api-reference/trading--demo/check-instrument-trading-eligibility), [what-if costs](https://api-portal.etoro.com/api-reference/trading--demo/get-what-if-trading-cost-breakdown), and [bid/ask rates](https://api-portal.etoro.com/api-reference/market-data/retrieve-bidask-rates-for-one-or-more-instruments).
