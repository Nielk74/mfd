# Demo BTC market entry probe

`btc-market-entry-probe-v2` is a one-time test of the provider-backed decision and order trail. It makes no claim that buying BTC has positive expected return. The fixed $100 notional tests eToro Demo execution with a small, explicit virtual-fund exposure. It is separate from the simulated AAPL/MSFT research scenarios.

The system records a **HOLD** unless all of these official eToro observations pass:

1. A schema-valid Demo account read is at most two minutes old, has a provider account ID, uses USD, has at least $500 available cash, and values the $100 plan at no more than 1% of the account. Aggregate holdings and copies are empty; the separate Demo P&L read has no positions or pending orders. The account ID is held as an HMAC fingerprint and must match again at execution.
2. Exact `BTC` instrument search says the instrument is tradable and buyable. A realtime bid/ask quote is at most 30 seconds old, not crossed, and has spread at most 50 basis points.
3. Account-specific eligibility permits a $100 unlevered long in the **real** BTC instrument, with minimum position size no greater than $100. The current what-if **market-order** estimate is at most two minutes old, has only recognized USD cost types, no nonzero ongoing fees, and upfront costs at most $2.

Passing preview creates a durable plan valid for 60 seconds. It shows the quote, source digests, checks, estimated upfront costs and a local recheck ceiling 0.2% above the observed ask. An explicit execute action repeats all provider checks and refuses submission if the ask rose above that ceiling. It persists the intent and broker request ID before one $100 `mkt` submission to the **Demo** v2 order endpoint. **The ceiling is not sent to eToro as a price limit:** a market fill may occur at a different price, and actual fees may differ from the estimate. The fixed order amount limits the requested investment to $100, plus actual costs. A successful submission response is only `accepted`; the official lookup by request reference, then returned order ID after a 404, supplies the broker state and position IDs. Ambiguous submissions are never resubmitted. Every successful raw provider response is encrypted in PostgreSQL.

If filled, the BTC position remains in the Demo account for observation in the scheduled portfolio snapshots. There is **no automatic exit, stop loss, fill accounting ledger, virtual sleeve allocation or claim of strategy performance** in this version. Review the broker position and account snapshots after the test; a later exit requires a separately designed and authorized close workflow. The shared operator token authenticates both human and agent calls to the same API, but it does not identify an individual person.

The earlier `btc-liquidity-probe-v1` used `limitIOC`. Its first hosted order was accepted for processing and then rejected by eToro with status 4 and error code 2039: the provider said this limit order was disallowed for the BTC instrument. No BTC position was opened. The broker's request-reference lookup returned 404, so reconciliation now uses the returned order ID as a fallback. That rejected decision remains in private history; v2 is a separate plan and request, not a retry of v1.

At 22:10 UTC on 27 September 2026, one v2 Demo market order filled. The broker lookup returned status 3 and one position ID; the official Demo P&L read showed one open position and no pending orders. MFD saved a new encrypted portfolio snapshot containing BTC. The lab displays this outcome under the Demo decision history; it does not infer profit or maintain a fill ledger from it.
